# سیاست زمان‌بندی آپلود یوتیوب OfferChin

تاریخ تصویب: ۱۴۰۵/۰۹/۰۱ (۲۲ نوامبر ۲۰۲۶)

## سیاست فعال

- حداقل فاصلهٔ بین هر دو تلاش آپلود یوتیوب: **۸ ساعت و ۱۵ دقیقه**.
- سقف عملیاتی این اتوماسیون: حداکثر **۳ تلاش آپلود در هر پنجرهٔ شناور ۲۴ساعته**.
- ساعت مشترک بین ویدئوهای محصول و ویدئوهای تحریریه است؛ هیچ‌کدام نمی‌توانند سهمیهٔ زمانی جداگانه‌ای مصرف کنند.
- زمان‌بندی از زمان موفقیت آپلود یا نتیجهٔ نامعلومِ درخواست آغاز می‌شود. نتیجهٔ نامعلوم هرگز با آپلود فوریِ مجدد دنبال نمی‌شود.
- خطای HTTP 429 نیز تلاش بعدی را حداقل به اندازهٔ فاصلهٔ مصوب عقب می‌اندازد.
- پاسخ صریح سقف روزانهٔ یوتیوب باعث توقف سراسری آپلود یوتیوب به مدت ۲۴ ساعت و ۱۵ دقیقه می‌شود؛ پس از پایان توقف، صف به‌صورت خودکار از سر گرفته می‌شود.
- آپارات و فیلو صف و ساعت مستقل دارند و به دلیل فاصله یا سهمیهٔ یوتیوب متوقف نمی‌شوند.

## پیاده‌سازی

- مقدار مرجع در `affilio_radar/affilio_radar.py` برابر `YOUTUBE_UPLOAD_INTERVAL_HOURS=8.25` است و مقدار کمتر از ۸٫۲۵ ساعت پذیرفته نمی‌شود.
- `youtube_next_upload_at` در state پایدار ذخیره و به `video_upload_dispatch_state.json` منتقل می‌شود.
- Cloudflare قبل از dispatch، ساعت جهانی یوتیوب و توقف احتمالی سهمیه را بررسی می‌کند.
- workflow اختصاصی یوتیوب و مسیر legacy/unified از یک concurrency group مشترک استفاده می‌کنند تا دو اجرای هم‌زمان نتوانند از یک ساعت قدیمی عبور کنند.
- مسیر انتشار تحریریه نیز پیش از هر آپلود همان ساعت جهانی را بررسی و پس از موفقیت/خطا به‌روزرسانی می‌کند.

## مرز تضمین

فاصلهٔ ۸ ساعت و ۱۵ دقیقه، حداکثر سه تلاش خودکار را در هر پنجرهٔ شناور ۲۴ساعته تضمین می‌کند، مشروط بر اینکه همهٔ آپلودهای کانال از همین اتوماسیون عبور کنند. آپلود دستی یا سامانهٔ دیگری که در همین کانال و در همین بازه ویدئو بارگذاری کند، در state این پروژه دیده نمی‌شود و می‌تواند سقف حساب/کانال را مصرف کند. سقف روزانهٔ حساب یا کانال از سهمیهٔ API جداست و مقدار آن باید از خود حساب یوتیوب مشخص شود؛ این زمان‌بندی به‌تنهایی نمی‌تواند محدودیت پایین‌تر یا رفتار آپلودهای بیرونی را خنثی کند.

طبق مستندات فعلی Google، متد `videos.insert` سهمیهٔ API جداگانه‌ای دارد: مقدار پیش‌فرض مستندشده ۱۰۰ فراخوانی در روز است و هر فراخوانی یک واحد از آن bucket مصرف می‌کند. سه تلاش در روز تنها حدود ۳٪ از این سهمیهٔ پیش‌فرض است؛ با این حال، quota واقعی پروژه باید در Google Cloud Console کنترل شود.

منابع رسمی:
- https://developers.google.com/youtube/data/determine_quota_cost
- https://developers.google.com/youtube/data/reference/rest/v3/videos/insert

## آزمون و بازگشت

آزمون‌های Python و JavaScript باید این موارد را بررسی کنند: رعایت فاصلهٔ ۸:۱۵، انتقال ساعت به sidecar، عدم dispatch زودهنگام یوتیوب، مستقل ماندن آپارات/فیلو و استفادهٔ مشترک دو workflow از قفل concurrency. تغییرات از branch و PR اعمال می‌شوند؛ در صورت بروز خطا، با revert کردن PR می‌توان سیاست را بازگرداند. فایل‌های state و سابقهٔ آپلود نباید پاک یا reset شوند.
