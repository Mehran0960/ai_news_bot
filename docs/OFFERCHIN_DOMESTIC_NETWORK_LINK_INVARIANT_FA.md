# اصل دائمی و غیرقابل‌مذاکرهٔ لینک افیلیت در شرایط اینترنت ملی ایران

> **شناسهٔ سیاست:** OC-NIN-001  
> **نسخه:** ۱.۰  
> **تاریخ تصویب:** ۲۰ نوامبر ۲۰۲۶  
> **سطح:** قانون اساسی فنی/محصولی OfferChin  
> **وضعیت:** دائمی؛ تغییر جهت تضعیف یا دورزدن آن ممنوع  
> **مرجع حاکم:** منشور پروژه و تمام PRها، workflowها، کدها، قالب‌ها و رسانه‌های OfferChin

## ۱. حکم اصلی

**مسیر کلیک کاربر روی CTA خرید باید بدون وابستگی به GitHub، Cloudflare، ردیاب کلیک، کوتاه‌کننده، واسطهٔ خارجی یا زیرساخت تحلیلی OfferChin کار کند؛ به‌نحوی که قطع یا محدودشدن اینترنت بین‌الملل در ایران، تا حدی که خود سرویس رسمی افیلیو و فروشگاه مقصد از شبکهٔ داخل ایران قابل دسترسی باشند، باعث شکستن مسیر لینک به‌دلیل معماری OfferChin نشود.**

این اصل برای همیشه الزام‌آور است. هیچ آزمایش A/B، افزایش درآمد، تغییر شبکه، بازطراحی، مدل هوش مصنوعی، feature flag یا تصمیم فنی مجاز به نقض آن نیست.

## ۲. زنجیرهٔ مجاز خرید

مسیر مجاز:

`کلیک آگاهانهٔ کاربر → لینک رسمی ناشر افیلیو → مقصد canonical همان محصول در فروشگاه مجاز`

- لینک باید توسط حساب/قالب رسمی و مجاز ناشر افیلیو تولید یا تحویل شود.
- در وضعیت فعلی، فقط قالب ناشر تأییدشدهٔ `https://aflo.ir/QekEYTRg?p=...` در validator پذیرفته می‌شود؛ هر تغییر host/path یا نوع لینک نیازمند تأیید رسمی افیلیو و آزمون کامل است.
- مقصد باید دقیقاً با شناسهٔ محصول و دامنهٔ فروشگاه مورد نظر تطبیق داشته باشد.
- CTA در محتوای نهایی باید همان لینک افیلیو معتبر را مستقیماً باز کند؛ نه URL ردیاب یا proxy.
- redirect داخلی خود شبکهٔ افیلیو که جزء سازوکار رسمی همان لینک است، واسطهٔ اضافهٔ OfferChin محسوب نمی‌شود؛ اما هر hop دیگری که توسط OfferChin یا ارائه‌دهندهٔ ثالث اضافه شود ممنوع است.

## ۳. ممنوعیت‌های مطلق در زنجیرهٔ CTA

موارد زیر نباید در مسیر کلیک خرید یا پیش‌نیاز بازشدن لینک قرار گیرند:
- Cloudflare Worker یا هر redirect/shortener متعلق به OfferChin؛
- GitHub Pages، GitHub Actions، سایت OfferChin یا هر صفحهٔ واسط؛
- ابزار آمارگیر، tracker، پیکسل، proxy، لینک‌ساز یا URL shortener ثالث؛
- JavaScript، API، DNS، asset CDN یا درخواست خارجی که برای resolve/ساخت لینک در زمان کلیک ضروری باشد؛
- صفحهٔ واسط تبلیغاتی، popup، iframe اجباری یا ریدایرکت پنهان.

تحلیل کلیک و انتساب باید مستقل از CTA انجام شود. خرابی tracker، داشبورد یا سرویس اتوماسیون نباید URL دکمهٔ خرید را تغییر دهد، آن را حذف کند یا مانع بازشدنش شود.

## ۴. قاعدهٔ دست‌نزدن به لینک امضاشده

- URL رسمی برگشتی Affilio باید بدون بازسازی، کوتاه‌سازی یا حذف پارامترهای آن استفاده شود.
- هر پارامتر رهگیری سفارشی، از جمله `aff_sub`، فقط پس از تأیید کتبی Affilio برای قالب دقیق لینک فعلی مجاز است.
- افزودن پارامتر با URL parser و بدون تغییر پارامترهای امضاشده انجام شود؛ رشته‌سازی کور، decode/encode چندباره یا جایگزینی host/path ممنوع است.
- `utm_source` و `utm_medium` جایگزین `aff_sub` یا تضمین انتساب سفارش نیستند.
- هیچ‌گاه لینک ناقص، منقضی، ناسازگار با محصول یا تأییدنشده به‌عنوان fallback منتشر نشود.

## ۵. آزمون دسترسی از داخل ایران؛ الزام پیش از انتشار

پسوند `.ir` یا نام دامنهٔ ایرانی به‌تنهایی اثبات نمی‌کند که لینک در اینترنت ملی باز می‌شود. دسترسی باید از داخل ایران آزموده شود.

برای هر host/path جدید یا هر تغییر در قالب لینک:
1. آزمون از حداقل دو مسیر مستقل اتصال داخل ایران (ترجیحاً دو اپراتور/ISP متفاوت) انجام شود.
2. DNS resolution، برقراری TLS/HTTPS، redirect chain، host نهایی، پاسخ مقصد و تطبیق شناسهٔ SKU ثبت شود.
3. آزمون برای Digikala و SnappShop جداگانه انجام شود؛ موفقیت لینک یکی، دیگری را اثبات نمی‌کند.
4. زمان آزمون به UTC و زمان محلی ایران، اپراتور/ISP، نوع اتصال، URL الگو با حذف اطلاعات حساس، status code و نتیجهٔ نهایی ثبت شود.
5. آزمون دوره‌ای حداقل هفتگی و نیز پس از تغییر DNS/دامنه/قالب افیلیو، اختلال سراسری یا گزارش کاربر اجرا شود.
6. تست انجام‌شده از GitHub runner یا خارج ایران، جایگزین تست داخل ایران نیست.

**محدودیت صریح:** تا زمانی که probe واقعی از شبکهٔ داخل ایران اجرا و گزارشش ثبت نشده، وضعیت دسترسی ملی «تأییدنشده» است؛ هرگز «تضمین‌شده» یا «تأییدشده» اعلام نشود.

## ۶. رفتار امن در زمان اختلال

- اگر لینک رسمی در یکی از شبکه‌های داخل ایران از دسترس خارج شد، آفر جدیدی که به آن مسیر وابسته است تا تعیین تکلیف در صف انتشار متوقف/معلق شود.
- لینک به یک کوتاه‌کننده، proxy، redirect شخص ثالث یا لینک مستقیم فروشگاه که انتساب افیلیت را از بین ببرد، خودکار تبدیل نشود.
- راه جایگزین فقط می‌تواند لینک/دامنهٔ رسمی دیگری باشد که افیلیو کتبی تأیید کرده و همان آزمون‌های داخل ایران را گذرانده باشد.
- اگر هیچ مسیر رسمی و آزموده‌شده‌ای وجود ندارد، توقف انتشار صحیح‌تر از انتشار لینک خراب یا از دست‌دادن پنهانی انتساب است.
- لینک‌های قبلاً منتشرشده بدون تصمیم کنترل‌شده و ثبت‌شده دستکاری انبوه نشوند.

## ۷. استقلال از سرویس‌های کنترل و انتشار

قطع GitHub Actions یا Cloudflare نباید:
- متن پست منتشرشده یا URL رسمی داخل آن را خراب کند؛
- برای بازشدن CTA نیازمند فراخوانی به سرویس جدید شود؛
- state، صف، cursor یا رسیدها را حذف یا از صفر شروع کند؛
- مسیر خرید را به redirect جایگزین تغییر دهد.

دارایی‌های ضروری برای تولید و انتشار (لوگو، فونت، قالب، تصاویر پایه و فایل‌های render) باید در مخزن/بستهٔ اجرا موجود باشند؛ دانلود CDN خارجی در لحظهٔ انتشار، پیش‌نیاز انتشار نباشد.

## ۸. گیت کد و تست رگرسیون

هر PR مرتبط با خرید/لینک باید دست‌کم این شروط را پاس کند:
- CTA برای تمام رسانه‌های فعال، URL رسمی معتبر افیلیو را بدون فراخوانی click tracker یا ساخت intermediary برگرداند.
- لینک نامعتبر/دامنهٔ ناشناخته/شناسهٔ محصول ناسازگار رد شود.
- خاموش‌بودن Worker، KV، API، داشبورد یا experiment attribution، URL CTA را تغییر ندهد.
- `aff_sub` فقط در صورت فعال‌سازی رسمی و با حفظ پارامترهای موجود قابل افزودن باشد.
- هیچ مسیر fallback غیررسمی به CTA اضافه نشود.
- آزمون network reachability داخل ایران به‌عنوان مدرک جداگانه ضمیمه شود و از CI خارج از کشور نتیجه‌گیری نشود.

این تست‌ها مکمل‌اند: تست کد تنها عدم وابستگی معماری به واسطه را اثبات می‌کند؛ دسترسی واقعی شبکه ملی فقط با آزمون از داخل ایران ثابت می‌شود.

## ۹. حاکمیت و تغییرناپذیری

این سیاست از نقشه‌راه درآمد، اهداف کمیسیون، بهینه‌سازی رسانه‌ها و سهولت پیاده‌سازی بالاتر است. هر تغییر پیشنهادی باید:
- دلیل فنی و اثرش بر مسیر CTA را در PR روشن کند؛
- تست‌های این سند را بدون حذف یا تضعیف بگذراند؛
- شواهد آزمون داخل ایران را ارائه کند؛
- در منشور، handbook و changelog ثبت شود.

**تغییر برای افزودن واسطه یا وابسته‌کردن CTA به اینترنت بین‌الملل رد می‌شود.** اگر در آینده سرویس رسمی افیلیو endpoint جایگزین داخلی/قابل‌دسترسی از اینترنت ملی ارائه کند، فقط پس از تأیید کتبی و آزمون مستقل می‌توان آن را به‌عنوان مسیر رسمی جدید پذیرفت؛ این استثنا به معنای مجازشدن واسطهٔ ثالث نیست.

## ۱۰. وضعیت نخستین ممیزی — ۲۰ نوامبر ۲۰۲۶

- تابع `tracked_affiliate_button_url()` در کد فعلی لینک معتبر Affilio را بدون واسطه بازمی‌گرداند.
- تست فعلی مستقیم‌بودن CTA وجود دارد، اما دامنهٔ پوشش آن به یک رسانه محدود بود؛ در همین PR برای تمام رسانه‌های تعریف‌شده گسترش می‌یابد.
- گزارش عملکرد زنده `direct_affilio_link` را تأیید می‌کند و click tracking زنده را false می‌داند.
- دسترسی از دو اپراتور/ISP داخل ایران در این ممیزی اجرا نشده است؛ بنابراین تاب‌آوری معماری در سطح کد برقرار است، اما قابلیت دسترسی واقعی Aflo و فروشگاه مقصد از اینترنت ملی هنوز تأییدنشده است.
- هیچ نتیجه‌ای دربارهٔ در دسترس بودن Aflo در شرایط ملی‌شدن اینترنت، بدون probe واقعی داخل ایران مجاز نیست.

**نتیجه:** اصل معماری لینک مستقیم در کد موجود است؛ گیت تست آن گسترش می‌یابد؛ آزمون واقعی شبکهٔ داخل ایران همچنان اقدام عملیاتی باز و اجباری باقی می‌ماند.
