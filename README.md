# OfferChin / آفِرچین

سامانهٔ پایش گستردهٔ کاتالوگ دیجی‌کالا و انتخاب پیشنهادها با اولویت سه معیار مستقل: **تقاضای زنده، عمومیت کاربرد و جذابیت تخفیف واقعی**. قیمت خود کالا معیار استطاعت یا جریمهٔ انتخاب نیست؛ قیمت جاری/اصلی فقط برای اعتبارسنجی محاسبات تخفیف و مبلغ صرفه‌جویی استفاده می‌شود.

## اصل عملیاتی انتخاب و انتشار

1. انتخاب از snapshot کامل کاتالوگ دیجی‌کالا انجام می‌شود؛ گزینهٔ مناسب صرفاً به یک دسته یا صفحهٔ محدود وابسته نیست.
2. رتبه‌بندی سه‌عاملی با میانگین هارمونیک انجام می‌شود: تقاضای زنده، عمومیت کاربرد و جذابیت تخفیف واقعی. تقاضای تازه و اعتبار آفر گیت‌های مستقل خود را حفظ می‌کنند. دادهٔ ناموجود جعل نمی‌شود.
3. قیمت و مبلغ صرفه‌جویی فقط در اندازه‌گیری ارزش واقعی تخفیف نقش دارند؛ گران‌بودن خود کالا، درآمد فرضی مخاطب یا پیش‌پرداخت اقساط امتیاز مستقل ندارند.
4. ارسال محصول پس از حداقل **۵۷ دقیقه** از آخرین ارسال موفق محصول مجاز است. اگر تعداد نامزدها در پنجرهٔ باقی‌مانده تا اسکن کامل بعدی جا نشود، تمام نامزدهای صف حفظ می‌شوند و زمان‌بندی آن‌ها به چرخهٔ بعد سرریز می‌شود؛ حذف یا فشرده‌سازیِ فاصله برای خالی‌کردن صف مجاز نیست.
5. محتوای تحریریه فقط در میانهٔ فاصلهٔ واقعی میان دو slot محصول قرار می‌گیرد. پست تحریریه ساعت ۵۷دقیقه‌ای محصول را reset نمی‌کند و هرگز محصولِ موعدرسیده را عقب نمی‌اندازد.
6. گاردهای تکرار مستقل‌اند: خانواده/شباهت/برند، دسته‌بندی و کاربرد. محدودیت دسته و کاربرد به‌صورت cooldownهای جداگانه عمل می‌کنند؛ نبود گزینهٔ مناسب باید باعث اسکن مجدد و انتخاب بهترین گزینهٔ واجد شرایط از کاتالوگ کامل شود، نه انتشار آفر نامعتبر.
7. رسید یا شناسهٔ واقعی هر مقصد معیار تأیید انتشار است؛ سبزشدن workflow به‌تنهایی اثبات انتشار عمومی نیست.

## کنترل تغییرات و گزارش

همیشه بین «هدف پروژه»، «رفتار فعلی کد» و «کار برنامه‌ریزی‌شده» تفاوت بگذارید. تمام تغییرات کد و تنظیمات OfferChin باید از مسیر PR مستند عبور کنند و در handbook و changelog ثبت شوند. اجرای زمان‌بندی‌شده‌ای که فقط دادهٔ runtime تولید می‌کند، از طریق Actions و state ledger ردیابی می‌شود.
