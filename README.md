## اصل عملیاتی

پس از عبور از گیت تقاضای تازه و اعتبارسنجی قیمت/موجودی/لینک، نامزدهای دارای دادهٔ کامل بر پایهٔ میانگین هارمونیک چهار معیار هم‌وزن مرتب می‌شوند: تقاضای زنده، استطاعت (proxy شفاف مبلغ ورود)، عمومیت کاربرد و جذابیت تخفیف. cohort قیمت فقط میان محصولات هم‌گروه و با حداقل ۸ مشاهده مقایسه می‌شود. رتبهٔ پرفروش سیگنال نسبی دسته است، نه تعداد قطعی فروش؛ رشد نظرها نیز فروش نیست. کلیک و کمیسیون ورودی رتبه نیستند. در نبود دادهٔ کافی، مقدار ساختگی تولید نمی‌شود و fallback قدیمی فقط برای حفظ رفتار سازگار باقی می‌ماند.

همیشه بین «هدف پروژه»، «رفتار فعلی کد» و «کار برنامه‌ریزی‌شده» تفاوت بگذارید. برای ادعای انتشار، post ID واقعی مقصد را بررسی کنید؛ موفقیت workflow به‌تنهایی اثبات انتشار عمومی نیست.

تمام تغییرات کد و تنظیمات OfferChin باید از مسیر PR مستند عبور کنند و در handbook و changelog ثبت شوند. اجرای زمان‌بندی‌شده‌ای که فقط دادهٔ runtime تولید می‌کند، از طریق Actions و state ledger ردیابی می‌شود.
