## اصل عملیاتی

ابتدا کاندیداهای دارای رتبهٔ تازهٔ پرفروش دیجی‌کالا را بر اساس قدرت/تازگی شواهد تقاضا، حرکت رتبه و پوشش دسته مرتب کنید؛ سپس رشد تازهٔ نظرها و زمینهٔ تاریخی ضعیف را لحاظ کنید؛ درصد تخفیف و savings_toman فقط پس از تساوی تقاضا وارد شوند. پلهٔ تخفیف صرفاً گیت اعتبارسنجی است. بعد از رتبه‌بندی، گاردهای rolling 24h خانواده، برند و شباهت را بر محصول اصلی و تمام fallbackها اعمال کنید. رتبهٔ پرفروش سیگنال نسبی دسته است، نه تعداد قطعی فروش؛ کلیک یا کمیسیون افیلیت نیز ورودی رتبه نیست.

همیشه بین «هدف پروژه»، «رفتار فعلی کد» و «کار برنامه‌ریزی‌شده» تفاوت بگذارید. برای ادعای انتشار، post ID واقعی مقصد را بررسی کنید؛ موفقیت workflow به‌تنهایی اثبات انتشار عمومی نیست.

تمام تغییرات کد و تنظیمات OfferChin باید از مسیر PR مستند عبور کنند و در handbook و changelog ثبت شوند. اجرای زمان‌بندی‌شده‌ای که فقط دادهٔ runtime تولید می‌کند، از طریق Actions و state ledger ردیابی می‌شود.
