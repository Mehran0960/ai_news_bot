# توسعهٔ پیام‌رسان‌های OfferChin

## سیاست هزینه و معماری

این توسعه از همان GitHub Actions و صف انتشار فعلی استفاده می‌کند. هیچ VPS، Make.com،
سرویس یکپارچه‌ساز پولی یا کتابخانهٔ وابسته به SaaS اضافه نشده است. خطای هر مقصد، تلگرام و بله را متوقف نمی‌کند.

رایگان‌بودن زیرساخت با رایگان‌بودن API پلتفرم یکی نیست. در مورد روبیکا، مسیر Bot API
مستقیم و مستند است و در این طراحی سرویس واسطه‌ای خریداری نمی‌شود؛ سقف‌ها یا شرایط مصرف
خود روبیکا باید از حساب سازندهٔ بات بررسی شود.

برای ایتا، مستند عمومی رسمیِ بررسی‌شده دربارهٔ ۵۰هزار اعتبار رایگان مربوط به
/api/app/sendMessage برای ارسال برنامه به کاربرانی است که اجازهٔ دریافت پیام داده‌اند.
این اعتبار، اثبات رایگان‌بودن ارسال فایل به کانال با Bot API نیست. به همین دلیل آداپتور
EitaaYar آزمایشی است و به‌صورت پیش‌فرض خاموش می‌ماند. پیش از استفادهٔ مستمر، تعرفه و
مجازبودن انتشار کانالی باید در پنل ایتایار تأیید شود.

سروش‌پلاس فعلاً متصل نشده است؛ مسیرهای یکپارچه‌ساز شناخته‌شده وابستگی بیرونی و احتمال
تعرفه ایجاد می‌کنند و مسیر رسمی رایگان برای انتشار خودکار کانال هنوز تأیید نشده است.

## تنظیم روبیکا

۱. از مسیر رسمی روبیکا یک بات بسازید.
۲. بات را به کانال OfferChin اضافه و مجوز ارسال پیام/فایل را به آن بدهید.
۳. شناسهٔ کانال مقصد را از مسیرهای مجاز روبیکا دریافت کنید.
۴. در GitHub مخزن ai_news_bot، مسیر Settings → Secrets and variables → Actions،
این Secrets را بسازید:

- RUBIKA_BOT_TOKEN
- RUBIKA_CHANNEL_ID

۵. در بخش Variables همین صفحه مقدار RUBIKA_ENABLE_PUBLISHING را true کنید تا انتشار
روبیکا فعال شود. تا قبل از فعال‌سازی این Variable، هیچ محتوایی به روبیکا ارسال نمی‌شود.

## تنظیم ایتا

۱. از ایتایار بات بسازید و دسترسی انتشار آن را در کانال مقصد مجاز کنید.
۲. این GitHub Actions Secrets را اضافه کنید:

- EITAA_BOT_TOKEN
- EITAA_CHANNEL_ID

۳. فقط پس از اطمینان از تعرفه، اعتبار و یک تست دستی کنترل‌شده، Variable
EITAA_ENABLE_PUBLISHING را true کنید. پیش‌فرض آن false است.

اگر ساختار پاسخ سرویس شناسهٔ پیام ندهد، سیستم فقط رسید پذیرش API را ذخیره می‌کند؛
شناسهٔ ساختگی تولید نمی‌کند.

## وضعیت انتشار

- sent یعنی API مقصد درخواست انتشار را پذیرفته/شناسه پیام برگردانده است؛ این وضعیت به‌تنهایی
تأیید مستقل مشاهدهٔ عمومی پست نیست.
- platform_message_ids فقط شناسه‌های واقعی برگشتی را نگه می‌دارد.
- platform_delivery_receipts رسیدهایی را نگه می‌دارد که API قبول کرده ولی شناسهٔ پیام نداده است.
- failed با زمان تلاش بعدی و backoff ثبت می‌شود.
- not_connected یعنی Secret/Variable لازم وجود ندارد یا آداپتور عمداً خاموش است.

## محدودیت‌های فعلی

- آداپتورهای جدید فقط پست تصویریِ محصول منتخب را ارسال می‌کنند؛ چرخهٔ ویدئو برای روبیکا و
ایتا در این مرحله اضافه نشده است.
- مقصدهای جدید فقط برای آیتم‌های صف جدید فعال خواهند بود و انتشار عمومی آیتم‌های قدیمی
به‌صورت خودکار به عقب برگردانده نمی‌شود.
- اجرای زنده پس از افزودن Secret/Variableها باید ابتدا با یک پست آزمایشیِ مورد تأیید مالک
کانال انجام شود.
